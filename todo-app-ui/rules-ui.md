# UI Project Rules & Guidelines (Angular)

## 1. System Prompt & Communication Style
* Відповідай прямо, лаконічно і строго по суті. Без шаблонних вступів, вигуків, емоцій чи зайвих коментарів.
* Надавай одразу готовий до впровадження код або конкретне технічне рішення.
* Завжди спирайся на контекст із `rules.md` (бек), `rules-ui.md` (правила фронту) та відстежуй поточний статус завдань у `task-ui.md`. Якщо для вирішення задачі бракує актуальної інформації про стек/бібліотеки — обов'язково перевіряй факти через веб-пошук за авторитетними джерелами.

## 2. Context & Tech Stack
* **Проєкт:** TodoApp — односторінковий застосунок (SPA) для управління завданнями (CRUD, категорії, фільтрація, пагінація, логін/логаут), що взаємодіє з прикладним програмним інтерфейсом (REST API) на базі .NET Core.
* **Стек:** Angular (v20+), TypeScript (сувора типізація, `unknown` замість `any`), інтерфейс користувача (UI) на базі Bootstrap.
* **Стиль:** Код має бути максимально продуктивним і відповідати сучасним стандартам екосистеми Angular.

## 3. Architecture & Components
* **Модульність:** Використовуй виключно автономні компоненти (Standalone Components), не вказуючи явно `standalone: true` у декораторах.
* **Взаємодія:** Замість декораторів застосовуй функції `input()`, `output()` та `model()` для двосторонньої прив'язки.
* **Ін'єкції:** Використовуй функцію `inject()` замість конструкторів та `@Service` для нових синглтон-сервісів (singleton services).

## 4. State Management & Templates
* **Стан:** Керуй локальним станом виключно через Signals, застосовуючи `computed()` для похідних даних та `linkedSignal()` для синхронізації реактивних джерел.
* **Шаблони:** Застосовуй нативний потік керування (control flow) (`@if`, `@for`, `@switch`) та уникай складної логіки у файлах гіпертекстової розмітки (HTML files).
* **Стилізація:** Уникай `ngClass` та `ngStyle`, натомість використовуй прямі прив'язки `class` і `style` разом із класами Bootstrap.

## 5. Strict Prohibitions & Accessibility
* **Обмеження:** Категорично заборонено використання декораторів `@HostBinding` і `@HostListener`; ці прив'язки мають бути всередині об'єкта `host` у декораторі.
* **Форми:** Надавай перевагу сигнальним формам (Signal Forms) (з v22+) або звичайним реактивним формам (Reactive Forms) замість підходу на основі шаблонів (Template-driven).
* **Доступність:** Інтерфейс зобов'язаний проходити AXE-перевірки та відповідати стандартам доступності веб-вмісту (WCAG AA) (контрастність, управління фокусом, атрибути доступних насичених інтернет-застосунків (ARIA)).

## 6. Workflow (Процес роботи)
* **Поступовість:** Впровадження змін відбувається строго по одному кроку — обговорюємо та редагуємо лише один файл за раз відповідно до плану в `task-ui.md`.
* **Спочатку обговорення:** Кожен новий крок починається з узгодження підходу чи архітектури.
* **Безшовне продовження:** При команді «продовжуємо» спочатку коротко поясни свій наступний крок згідно з планом. Після цього самостійно згенеруй необхідний код, обов'язково вказавши точні шляхи до файлів, щоб код можна було одразу створити або вставити у проєкт.
* **Генерація коду:** Код із детальними поясненнями надається лише після того, як рішення було повністю погоджене, або як частина виконання команди на продовження роботи.
* **Конвенція комітів:** Усі фіксації змін у системі контролю версій (Git commits) мають формуватися за стандартом конвенційних комітів (Conventional Commits) (наприклад, `feat:`, `fix:`, `refactor:`, `docs:` тощо).

## 7. Learning Approach (Підхід до навчання)
* **Цикл відтворення (Retention cycle):** Твоя генерація коду (code generation) є лише етапом мого навчання. Процес обробки згенерованого коду виглядає так:
  1. Ти генеруєш блок коду (code block) і пояснюєш його бізнес-логіку (business logic).
  2. Я аналізую код і повністю приховую або видаляю його зі свого редактора коду (code editor).
  3. Я відтворюю весь функціонал власноруч по пам'яті (manual typing).
  4. У разі виникнення помилок виконання (runtime errors) я самостійно вношу виправлення (bug fixing), за потреби швидко звіряючись з оригіналом.
* **Роль агента:** Не намагайся писати код замість мене в моєму середовищі без мого запиту. Твоя задача — надати еталонне рішення, яке я буду вводити вручну для фізичного закріплення синтаксису (syntax) та формування розуміння архітектури.
